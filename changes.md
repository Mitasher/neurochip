# changes.md — что изменено и зачем

Документ описывает правки, внесённые в проект «SEU-устойчивость: фон-Нейман vs
нейроморф (AltAI)» по запросу: сделать прозрачными **вход → изменение → выход**,
убрать неточности, перенести проверку нейроморфа **прямо на эмулятор чипа AltAI**
и **разделить вывод на два эксперимента** (линейная алгебра и перцептрон).

---

## 1. Проверка нейроморфа теперь идёт ПРЯМО НА ЧИПЕ AltAI

**Было.** 100 эмуляций битфлипа для нейроморфа считались на numpy-модели LIF
(`platforms/neuromorph.py`), а реальный golden model AltAI трогался только в
отдельной сверке на «чистых» входах. То есть сам SEU-эксперимент шёл на имитации,
а не на чипе.

**Стало.** Инъекция в синапс выполняется на реальном эмуляторе чипа AltAI
(`inference_type='gm'`):

- новый модуль [`platforms/altai_chip.py`](platforms/altai_chip.py) — класс
  `AltaiChip`: строит эталонный placed-конфиг (кэш), исполняет вход на чипе,
  а для каждого сбоя **пересобирает конфиг под повреждённые веса** и заново
  запускает чип;
- эталонный и сбойные прогоны читают спайки прямо из `get_spikes()`.

**Почему именно пересборка, а не точечная правка синапса.** Метод
`reload_neuron_synapses` существует, но Placer разносит MAC одного слоя по сетке
ядер (здесь 32×4) с непрозрачной раскладкой синапсов — у выходного нейрона на
ядре веса не совпадают с (row, col) исходной матрицы. Надёжно адресовать один
синапс на собранном чипе нельзя, поэтому единственный достоверный способ внести
сбой в вес «в железе» — пересборка под новую матрицу (~18–24 с на сборку).
Из-за стоимости сборки на чипе прогоняется меньше инъекций (`N_CHIP_SYNAPSE=18`),
чем на быстрых numpy-моделях (`N_TRIALS=100`) — это осознанный компромисс,
явно отражённый в выводе.

---

## 2. Исправлена неточность в «линейном выходе» нейроморфа

При запуске на чипе выяснилось: одиночный слой `TernaryDense+Heaviside` выдаёт
**ровно один спайк на активный нейрон** — то есть нативный выход чипа это
**бинарный знаковый вектор** `b ∈ {0,1}` (`b_j = 1 ⇔ (W·x)_j > 0`).

Прежняя numpy-модель считала «линейный выход» как счётчик спайков до `N_TICKS=24`
и читала argmax по проинтегрированной мембране — **этого чип не делает**.
Поэтому:

- линейный выход нейроморфа теперь определён так, как его реально выдаёт чип —
  знаковый вектор `{0,1}` (ограниченная амплитуда, без «магии» накопления);
- решение перцептрона на чипе определено как **множество спайкующих нейронов
  (active set)** — чип это пороговый детектор знака и по величине НЕ ранжирует;
  смену именно этого множества мы и считаем повреждением решения
  (`metrics.decision_outcome`). Притворяться, что чип считает `argmax` по
  величине, мы перестали.

## 3. Вывод разделён на два эксперимента

Структура `results/seu_report.json` и весь отчёт теперь явно делятся на:

- **`experiment_1_linear_algebra`** — `y = W · x`. Метрика: норма отклонения
  выходного вектора `‖Δ‖/‖ref‖`.
- **`experiment_2_perceptron`** — `class = argmax(W · x)` (на чипе — знаковый
  паттерн). Метрика: частота смены решения классификатора.

Каждый эксперимент содержит результаты по всем платформам
(`vonneumann_float32`, `vonneumann_int8`, `neuromorph_altai_chip`) и флаг
`on_chip`, показывающий, где реально считалось.

Самовосстановление мембраны вынесено в отдельный блок
`supplementary_membrane_model` с явной пометкой **«numpy-модель, НЕ на чипе»**:
golden model в режиме `gm` не выдаёт состояние нейрона во время счёта, поэтому
инъекцию в мембрану на чипе сделать нельзя (`get_ns()` пуст). Раньше это
подавалось как свойство нейроморфа без оговорки — теперь честно помечено.

## 4. Подробный вывод «вход → изменение → результат»

- в JSON у каждой платформы есть `traces` — список прогонов:
  `fault` (где и какой бит перевёрнут, старое → новое значение),
  `before`/`after` (выход до и после), флаг смены решения / отклонение;
- для чипа сохраняются ВСЕ прогоны (их немного), для numpy-моделей — первые
  `TRACE_SAMPLES=6`;
- консоль и `report.py` печатают вход (`W`, `x`, эталонные `W·x`, класс,
  active set) и итоги по каждому эксперименту отдельно;
- в `meta.input` сохранены сами `W` и `x`, в `meta.golden` — эталонные
  логиты, класс и знаковое множество.

## 6. Как запускать

```bash
source venv/bin/activate

# инъекция в синапс — на эмуляторе чипа AltAI (по умолчанию); остальное на numpy
python seu_experiment.py

# всё на numpy-моделях (быстро, без чипа)
python seu_experiment.py --no-chip

# + сверка numpy-модели нейроморфа с чипом на чистых входах
python seu_experiment.py --altai-validate

# таблицы и графики по двум экспериментам
python report.py
```
